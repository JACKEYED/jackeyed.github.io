## 背景

「智心羽 AI」是家育宝面向 K12 学生与家长的对话式心理健康产品，已在各大应用商店上线。我在实习期间负责多智能体对话系统的算法侧——从路由、角色 Agent、检索，到长期记忆和安全兜底。

这个场景有几个特殊约束，决定了后面的所有设计取舍：

- **用户是未成年人**，误路由和有害输出的代价很高；
- **陪伴 ≠ 问答**，用户要的往往不是"正确答案"，而是"被接住"；
- **危机内容必须零幻觉**——援助热线号码绝不能让 LLM 生成。

## 系统总览

```text
用户消息 (user_id, session_id, message)
      │
      ▼
┌─────────────────────────────────────────────┐
│  情绪路由 Agent  (EmotionRouterAgent)        │
│   ① 会话摘要   ② 情绪信号   ③ 角色推荐        │
└───────┬─────────────────────────────┬───────┘
        │ handoff                     │ 情绪回流
        ▼                             │
┌───────────────────┐                 │
│  物件人格 Agent    │ ── 情绪显著变化 ─┘
│  (14 个独立子图)   │
│  纸巾盒 / 梳子 /   │      ┌──────────────┐
│  沙袋 / 毛毯 ...   │──────│ 三层长期记忆 │
└─────────┬─────────┘      │ 摘要/抽取/整理 │
          │                └──────────────┘
   ┌──────┴───────┐
   ▼              ▼
┌────────┐   ┌──────────────────────┐
│ 技能   │   │ 检索层 (心理/百科)    │
│ HTML   │   │ 年龄过滤→扩展→HyDE→   │
│ 小游戏 │   │ 向量/BM25→RRF→rerank  │
└────────┘   └──────────────────────┘

贯穿全程：两级危机检测（关键词 + LLM 复核）
```

算法端在 v3.0 重构后**完全无状态**：每次请求靠入参驱动，历史 / 状态 / 长期记忆由业务后端注入，记忆写入以 buffer 形式随响应返回，由后端异步落库。这让算法服务可以随意水平扩容。

## 情绪路由 Agent

路由不是简单的"选一个 agent"，而是拆成三个阶段，各自用一个小模型完成：

| 阶段 | 职责 | 产出 |
| --- | --- | --- |
| **会话摘要** | 增量维护当前会话的情绪脉络与关键事件 | `session_summary` |
| **情绪信号** | 判断这一轮情绪是否显著变化、是否需要回流到路由 | `emotion_signal` |
| **角色推荐** | 结合摘要 + 信号 + 14 个 agent 的画像，给出「陪伴角度」建议 | 推荐 agent + 引导话术 |

关键决策：**路由只做软建议，不强制切换**。识别到当前角色不匹配时，返回"要不要试试 X"给前端，由用户自己选。原因是把一个求安慰的孩子自动转给"毒舌吐槽"角色，代价太高。

路由和子 Agent 之间通过 **handoff summary** 交接——子 Agent 拿到的不是整段历史，而是路由蒸馏过的一小段上下文，避免人格"串味"。当情绪信号检测到明显转折（比如从"愤怒"转向"低落"），触发**情绪回流**，重新回到路由阶段重新推荐。

## 14 个「物件人格」Agent

产品把每种陪伴方式拟人化成一个物件：吸泪纸巾盒（只递纸巾不讲道理）、顺毛小梳子（无条件站你这边）、出气小沙袋（一起吐槽不劝和）、恒温小毛毯（缓解孤独）……每个角色有明确的**陪伴角度**和**红线**。

工程上：

- 每个角色是一个**独立的 LangGraph 子图**（`graph.py` / `llm.py` / `prompts.py` / `states.py`），共享一套 common 基类；
- 角色元信息（画像、场景、采样参数、是否带技能）集中在一份 registry，路由阶段直接读这份画像做推荐；
- 部分角色挂**技能**——HTML 小游戏（呼吸泡泡、出气沙袋等），由 Agent 在合适时机推给前端，文件走 CDN 托管，算法服务本地不需要这些资源也能跑。

新增一个角色 = 加一份子图 + 一条 registry 记录，路由无需改动。

## BERT 意图 / 年龄分类器

对话进入检索类角色前，先用一个**自训练的 BERT 多标签分类器**判断 Query 属于哪个能力域、面向哪个年龄段（学龄前 / 小学 / 初高中），用来路由和过滤知识库检索范围。

训练上做了几件事对抗类别不均衡和边界模糊：

- **多标签三头输出** + 每头独立阈值，允许"小学 + 初中"这种跨段样本；
- 损失是**动态加权组合**：Focal Loss + 标签平滑 + 语义正则，权重随训练阶段自动调度（前期重 focal 压难样本，后期加大标签平滑防过拟合）；

$$
\mathcal{L}_{\text{focal}} = -\alpha\,(1 - p_t)^{\gamma}\,\log p_t
$$

- **关键词 + 模型混合判定**：能被规则（年龄数字、"上几年级"）确定的直接短路，不确定的才过模型，省一次前向；
- cosine 学习率 + warmup + 早停 + 梯度裁剪，让小数据集上的训练稳定收敛。

## 检索层

心理博士和百科角色共用一条检索管道，为生成提供**可追溯**的知识上下文：

```text
Query
 → 年龄段识别（关键词 + Qwen 兜底）
 → LLM 查询扩展（生成若干语义改写，保留原问）
 → 向量编码 + LRU 缓存
 → HyDE 判断：Top-1 相似度低于阈值时，让 LLM 生成"假设答案文档"再编码
 → 多库并行召回：向量检索 ⟂ BM25(ik_max_word) 检索
 → RRF 融合（不依赖分数绝对尺度）
 → 混合去重（SequenceMatcher / MinHash 按候选量切换）
 → CrossEncoder 精排
 → Top-K 片段 + 引用来源
```

RRF 分数：

$$
\text{RRF}(d) = \sum_{i} \frac{1}{k + \text{rank}_i(d)}
$$

心理场景是"共情型"输出（先理解情绪、再分析、最后给可执行建议），百科场景是"事实型"输出（关键事实带 `[n]` 角标），两者用不同的生成 prompt。

## 三层长期记忆

参考 Claude Code 的记忆设计，按**三种时间尺度**分层，而不是往一个大文件里追加：

| 层 | 触发 | 作用 |
| --- | --- | --- |
| **会话摘要** | token / 轮次达到阈值，或当前轮自然收束 | 压缩当前会话上下文，保留中间决策与未完成事项 |
| **事实抽取** | 完整轮次结束后，异步、增量（按 `last_processed_message_id`） | 把用户昵称、偏好、近期事件等 durable fact 沉淀成 topic 文件 + 索引 |
| **低频整理** | 时间门控 + 会话数门控 + 锁 | 归并重复 topic、删过时内容、把"上周"这类相对时间改写成绝对时间 |

抽取和整理都在主线程外跑，不阻塞对话；主 Agent 已经自己写过的记忆，后台会跳过避免重复。

## 安全：两级危机检测

这是产品的安全底线，贯穿所有角色：

```text
用户消息
  │
  ├─ 关键词层：扫"自杀 / 自残 / 活着没意思"等强信号
  │     未命中 → 正常对话
  │     命中 ↓
  ├─ LLM 复核层：区分真实求助 vs 吐槽 / 玩笑（"作业多到想死"≠ 危机）
  │     confirmed = False → 正常对话
  │     confirmed = True ↓
  └─ 固定转介话术（模板，非 LLM 生成）：
        共情承接 + 全国心理援助热线 + 急救提示 + 免责声明
        → 绕过常规生成直接返回
```

设计要点：**宁可误触发多打一次 LLM，也不能漏**；**援助热线和转介话术绝不交给 LLM**——一个幻觉出来的错误号码可能让求助失败。

## 复盘

- 这个项目让我第一次完整地把"多 Agent"从 demo 做到线上：难点不在单个 Agent，而在**路由、交接、回流、记忆、安全**这些"胶水"，以及它们在无状态约束下如何组织。
- **拟人化是产品的，不是技术的**——真正让陪伴有效的是每个角色清晰的"红线"和"陪伴角度"，prompt 里写"会说'你这题怎么又错了'但不会人身攻击"，比写"严厉"有用得多。
- 危机检测这条线上，我更愿意接受工程上的"笨"（关键词 + 固定模板）换取确定性。有些地方就是不该让模型自由发挥。
