## 角色

在一家金融量化公司实习，独立负责三个 AI 驱动的工程系统。我主导架构设计与量化投研领域建模，把系统拆成清晰的模块与阶段，并对每一项产物逐条验收。

三个系统面向的问题不同，但共享同一条设计主线——**可审计**：每一步的输入、判断、产物都留痕，可回溯、可回滚，人工只在真正需要时介入。

## AIFinance —— AI 因子研究工程系统

把「读研报 → 提出因子 → 验证因子」这条链路做成一条**可审计的串行流水线**：

```text
研报 PDF
  → 研报解析（MinerU）
  → LLM 文本清洗
  → 因子提案抽取
  → GP 表达式生成
  → 因子值计算
  → 多维回测验证：IC / FDR / 样本外 / walk-forward / 跨市场态
  → review · advisory · reflection 闭环
```

关键设计：

- **「文档–运行」分层 + 质量卡机制**。按原始字节的 **SHA-256** 确定文档身份，同哈希只存一份；每一次运行独立留存系统判断、人工裁决、产物哈希与质量卡。上游阶段没通过时，下游只读等待，不会拿到半成品往下跑。
- **「仅规则命中才需人工介入」的干预模型**。绝大多数样本全自动流过，只有触发预设规则的样本才停下来等人；人的时间花在真正模糊的判断上。
- **分层依赖 + 单一 LLM 边界**。`contracts + 7 个功能模块 + runtime 单一 composition root` 的分层结构，所有 LLM 调用**收敛到一个边界模块**——换模型、加缓存、做审计，只改一处。

## SignalDeck —— 竞品情报监控系统

Node.js，约 2 万行代码、约 300 个测试。核心是一个**竞品评级引擎**：

```text
多源召回
  → BGE-M3 语义粗筛
  → 两轮 LLM 事实提取 + 独立核验
  → 规则引擎定级
```

定级规则是**锚点式**的，不靠模型「感觉」：

- **12 条结构性硬淘汰规则**先过一遍；
- **P0 / P1 准则**要求「生成 / 定量验证 / 回测」三个锚点**都有源码级证据，且连成同一条工作流**——不是各自独立存在就算。

为了让规则稳，我搭了一个 **80 样本的校准闭环**：混淆矩阵 + 逐项 criteria 归因，反复收紧规则，**显著降低「把普通项目误判成 P0」**。历史积压结果按准则版本分桶，避免旧标准的结论污染当前视图。

另外两块能力：

- **源码级竞品对比**：拉取双方固定 commit 的源码，让 LLM 逐项对比功能 / 流程 / 架构 / 实现差异；
- **自研工程知识地图**：LLM 通读全量代码，生成 **10 项能力的流水线画像**，代码更新时增量重建。两者都被技术雷达和源码对比复用。

工程上是**异步扫描流水线** + 逐阶段进度上报 + 飞书四张表同步。

## TaskHub —— 局域网研发协作控制面

把「研发一个任务」拆成**不可跳过的可审计阶段**：

```text
只读生成方案
  → 人工确认
  → 独立 git worktree 开发
  → 代码聚焦的轻量测试
  → Runner 计算 patch digest
  → 独立只读 Review Agent 审核
  → 人工确认整改
  → 推送功能分支
```

强制约束：

- **Development Agent 不得自审**——审核由一个独立的、只读的 Review Agent 做；
- 不允许绕过方案确认、质量报告、patch digest 绑定；
- 每位开发者本机跑一个 Runner 调用原生 Codex，**中央 Dashboard / API 统一编排多人协作与归属**。

它把「用 AI 写代码」从个人行为变成了一个团队里可管理、可追责的流程。

## 复盘

- **可审计不是额外功夫，是让 AI 系统能被信任的前提**。留痕、分阶段、单一边界、独立审核——这些约束一开始看着「重」，但正是它们让系统在出错时能定位、能回滚、能交给别人维护。
- 系统能不能做成，取决于架构和领域模型是否切得够干净、验收标准是否可执行——写「严格校验」不如写「这三个字段缺任一个就拒绝，返回 422」。把模糊的需求逼成可执行的规格，是这三个系统里我花时间最多、也最有价值的部分。
